# ST-4605: iOS app lock

## Context & Objective

ST-4605 splits the optional iOS app lock out of ST-4596.  The Keychain session-cookie work stays on PR #5131.  App lock does not call that code, so this branch is based on current main.

## Changes Made

Optional device gate, off by default.  Face ID, Touch ID, or the device passcode is required after launch and after the app has been in the background for more than one minute.  If the device cannot authenticate, the setting cannot be turned on, and a lock that is already on offers Turn Off App Lock instead of trapping the user.

## Decisions & Trade-offs

- Based on `main`, not `gb-engineer/st-4596-ios-keychain-app-lock`. No `SessionKeychain`, cookie jar, or `MobileStore` persistence changes.
- The timeout is a fixed 60 second grace, not a picker.  Returning inside the window clears the background timestamp so a later render does not lock the app while it is still in the foreground.
- The policy is `LAContext.deviceOwnerAuthentication`, so the system falls back to the device passcode.  `localizedFallbackTitle` stays unset so a custom button does not replace that passcode UI.
- Device-auth availability is injected in tests so XCTest does not depend on simulator enrollment.
- Foreground resume reloads before it starts the live stream.  A background during that reload does not start the stream.

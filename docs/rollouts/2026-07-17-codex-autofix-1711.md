# Codex Autofix Round 1 — PR #1711

**Summary:** Addressed 4 Codex review findings on `monet/usage-push-failsafe` (circuit-breaker + bounded buffer for usage-monitor push) in a single `[codex-autofix]` commit.

**Files touched:**

**Fixes:**

1. **P2 (line 695) — Trim expired events at the start of each flush.** Added `trimBufferedEvents(Date.now())` at the beginning of `flushUsageMonitor` before any drain path. Previously trimming occurred only on enqueue, resolution failure, or send failure, letting events age past TTL during an open breaker.

2. **P2 (line 229) — Migrate HMR queue entries to current wrapper shape.** Added migration on state load: items in `state.queue` that lack the `receivedAt` number property (legacy pre-v4 raw `UsageMonitorEvent` objects) are auto-wrapped into `{ event, receivedAt }`. Prevents the resolved batch from passing `undefined` entries to the shared client.

3. **P1 (line 727) — Time out live push attempts before relying on the breaker.** Added `PUSH_SEND_TIMEOUT_MS = 30_000` with an `AbortController`/`AbortSignal` pass-through to `createUsageTelemetryClient`'s fetch, matching the pattern already used in `sendUsageMonitorBatch` for the replay path. Prevents a hung `client.send` from blocking `breakerRecordResult` forever.

4. **P2 (line 182) — Bound high-cardinality call-volume aggregation.** Added `MAX_CALL_VOLUME_KEYS = 100` cap on the `callVolume` map. When the map exceeds the cap, oldest entries are evicted (preserving insertion-order semantics). Prevents unbounded memory growth during a breaker-open period.

## Refinement (MONET reconciliation commit, same day)

The first-pass autofix above was correct in mechanism but diverged from the coordinator's explicit
spec on two knobs and left gaps. A follow-up MONET reconciliation commit refined it (see
`2026-07-17-usage-monitor-push-failsafe.md` "Review round" for full detail):

- **Timeout (finding 3):** made env-tunable `USAGE_MONITOR_PUSH_TIMEOUT_MS` (default **10s**),
  replacing the hardcoded `PUSH_SEND_TIMEOUT_MS = 30_000`. The coordinator asked for an env knob
  with a ~10s default; 30s is too long for the live path.
- **callVolume cap (finding 4):** made env-tunable `USAGE_MONITOR_CALLVOLUME_MAX_KEYS` (default
  **2000**), replacing the hardcoded `MAX_CALL_VOLUME_KEYS = 100`; evicts oldest-inserted lanes
  *before* inserting a new key rather than after.
- **HMR migration (finding 2):** now migrates BOTH `queue` and `pendingQueue` (the autofix migrated
  only `queue`, leaving pre-v4 pendingQueue entries with an `undefined` `receivedAt`) via a named
  `normalizeRetainedQueues()`, and bumps `STATE_VERSION` 3→4 so the stale-timer path also fires.
- **Tests:** the autofix added none; the reconciliation adds 11 focused tests covering all four
  findings (push timeout → breaker trip, callVolume distinct-key cap, flush-entry TTL drop, and the
  pre-v4 HMR queue-shape migration), plus the earlier breaker/buffer tests.

Post-reconciliation gate: `tsc` clean, lint 0 errors, focused **28/28**, full 404 files/**4741**
tests, production build clean.

# 2026-07-04 - w1-llm-fixes (composite review Wave-1, LLM-fixes lane)

## Summary

Five targeted fixes from the 2026-07-04 composite expert review (sections B and E),
scoped to `claude/w1-llm-fixes` (one of four parallel Wave-1 lanes coordinated off
that review):

1. **Fix the Bear schema silently stripping `confidenceScore`** (B/high/S — live
   money-path bug). The inline Bear (Red Team) structured-output schema
   (`strategy.ts` `bearSchema`) omitted `confidenceScore` from both `properties`
   and `required` while `additionalProperties: false` forbid the model from
   re-emitting it — every Bear-surviving proposal's confidence silently became
   `undefined` after `sanitizeProposals`' `clampConfidence(undefined)`. That
   zeroed `shouldRunRedTeamDebate`'s `?? 0` approval-time trigger, degraded
   sizing to a neutral `?? 50`, and fed the wash-sale auto-edge math the same
   undefined. Fixed by adding `confidenceScore` back to the Bear schema
   (properties + required) and instructing the Bear (`buildBearSystem`) to
   PRESERVE the Bull's score unless deliberately revising conviction (and to say
   so in the rationale when it does).
2. **Reasoning-token headroom for non-OpenAI providers** (B/high/S).
   `withLlmRequestBounds` previously added extra output-token headroom for
   hidden reasoning tokens ONLY in the OpenAI branch; xAI/Gemini/Mistral/
   DeepSeek chat-completions calls kept the bare 1500-token visible cap even at
   medium/high reasoning effort, so a hard-thinking non-OpenAI call could spend
   its whole budget on hidden reasoning and truncate the visible JSON answer.
   Extended `REASONING_TOKEN_BUDGET` to cover every effort level
   (`minimal`/`low`/`medium`/`high`/`xhigh`/`max`) and applied the same headroom
   calculation to every reasoning-capable chat-completions provider, not just
   OpenAI.
3. **Cross-family Bear default + non-zero adversary temperature** (B/medium/S).
   `redTeamLlmModel` now defaults to a model from a DIFFERENT provider family
   than the Bull (`claude-haiku-4-5` for a non-Anthropic Bull; `gpt-5.4-mini`
   for an Anthropic Bull) — but ONLY when a credential for that cross-family
   provider is actually configured; otherwise it falls back to today's
   same-family behavior so an unconfigured single-provider setup is never
   silently broken (advisory, non-paternalistic default — see Deviations).
   Both the inline Bear (`strategy.ts`) and the separate high-conviction
   `debateProposal` (`red-team.ts`) now sample at `temperature: 0.7` (new
   `LLM_REQUEST_DEFAULTS.adversaryTemperature`) instead of the Bull's
   deterministic 0, via the same `withLlmRequestBounds` path (added a
   `temperature` field to `LlmRequestSpec`/`buildLlmRequestBody`).
4. **Reward abstention in the Bull schema** (B/medium/S). Added an explicit
   line to `buildBullSystem`: "Returning ZERO proposals is a CORRECT and often
   the RIGHT outcome... Do not manufacture a proposal just to have output."
5. **Stakes-scaled dissent** (E quick-win). `shouldRunRedTeamDebate` gated on
   `confidenceScore` alone, so a low-confidence but large-notional LIVE trade
   got no adversarial review while a high-confidence $50 paper trade did. Now
   ANY of the following also triggers the debate: notional at/above a new
   policy-tunable `redTeamNotionalPctOfNavThreshold` (default 15% of NAV),
   a LIVE opening (buy/short on a non-paper account), the proposal itself
   requesting an `autonomyOverride`, or an escalation-regime entry
   (`isEscalationRegime`). Advisory routing only — this only decides whether a
   review runs, never a block. The verdict receipt (`TradeProposal.redTeamVerdict`)
   now carries an optional `trigger` field recording which condition fired
   (`confidence` | `notional` | `live_opening` | `override_requested` |
   `escalation_regime`).

`STRATEGY_PROMPT_VERSION` bumped `agentic-strategy@1.3.0` -> `agentic-strategy@1.4.0`
for the prompt-visible changes (items 1 and 4).

## Deviations

- The composite review says to simply "default `redTeamLlmModel` to a different
  family than the Bull." A literal always-on cross-family default breaks any
  environment/account that has only ONE provider's API key configured (the
  Bear/debate would resolve to a model with no credential, fail closed, and
  route every high-conviction/notional/live proposal to human review instead of
  autonomous "decide" execution — confirmed by running the existing test suite
  with the naive always-on version, which broke ~8 pre-existing tests that only
  stub an OpenAI key). Implemented instead as: default to the cross-family
  model ONLY when a credential for that provider is actually resolvable for the
  user; otherwise keep the current same-family fallback. This preserves the
  spirit of the fix (a configured multi-provider owner gets genuine cross-family
  review by default) without silently degrading a single-provider setup — in
  line with the repo's binding "no paternalistic defaults / no silent breakage"
  philosophy.

# axios 1.18.0 to 1.20.0

## Context & Objective

Dependabot PR #4014 bumps the axios version installed by the production Dockerfile `npm ci`.  The next operator needs the verification and deploy context for that runtime change.

## Changes Made

- `package.json` raises the `overrides.axios` entry from `^1.18.0` to `^1.20.0`, and `package-lock.json` resolves axios 1.20.0, plus this handoff.
- The override is not a lockfile refresh: it forces the bundled broker SDK `@alpacahq/alpaca-trade-api@3.1.3`, which declares `axios: ^0.21.1`, onto axios 1.20.0, a major-version jump outside the SDK's declared range on the money-path HTTP client used for broker orders.
- No application code change in this PR.  Axios consumers: `@alpacahq/alpaca-trade-api@3.1.3` (forced to 1.20.0 via `overrides.axios`) and first-party `src/lib/alpaca.ts`, which `require`s the same bundled axios instance and sets `sdkAxios.defaults.timeout = ALPACA_BROKER_IO_DEADLINE_MS` on the money-path broker client (Node HTTP adapter).

## Decisions & Trade-offs

- Merge.  1.20.0 hardens runtime option reads against prototype pollution.  `PayloadTooLarge` and `UnprocessableEntity` stay as deprecated aliases of the new RFC 9110 names.
- The XHR change (navigation cancel rejects with `ECONNABORTED` instead of resolving status 0) does not apply.  This repo does not use the browser XHR adapter.
- `PLAN.md` and phase docs are intentionally untouched.  This bump does not change product scope or a phase design.

## Verification State

The lockfile commit passed the required `verify` gate: `npm run lint`, `npx tsc --noEmit`, `npm test`, and `npm run build`.  The full Next.js build passed.  `gitleaks` passed.  This docs commit remains incomplete until it passes the same exact gate.

Tracking references: PR #4014 and GitHub issue #4175.

## Zero-Code Findings

- The override already existed at `^1.18.0` on main, so the SDK already runs outside its declared `^0.21.1` range in production.  This PR moves it 1.18 to 1.20 within the same major.
- `@alpacahq/alpaca-trade-api@3.1.3` is forced onto axios 1.20.0 via `overrides.axios` in `package.json`.
- First-party `src/lib/alpaca.ts` (around lines 113-114) is also an axios consumer: it uses `require("axios")` so it mutates the same CommonJS instance the bundled SDK uses, and sets `sdkAxios.defaults.timeout = ALPACA_BROKER_IO_DEADLINE_MS` on the broker order path.  Comments in that file document why ESM `import axios` would not reach the SDK's instance.
- The Alpaca SDK uses the Node HTTP adapter, so the XHR navigation-cancel change does not apply.
- Axios 1.20.0 hardens prototype-pollution-safe *reads* when merging config (own properties on reads).  This repo additionally *writes* shared axios defaults (timeout) in `alpaca.ts`, so the money-path surface is not SDK-only.  The renamed error classes keep deprecated aliases.
- Risk is that a forced major override on the broker HTTP client is untested by the SDK maintainers.  The evidence relied on is the repo's `npm test` suite plus the full build under the required `verify` gate.

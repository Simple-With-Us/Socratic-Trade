# axios 1.18.0 to 1.20.0

## Context & Objective

Dependabot PR #4014 bumps the axios version installed by the production Dockerfile `npm ci`.  The next operator needs the verification and deploy context for that runtime change.

## Changes Made

- `package.json` and `package-lock.json` only, plus this handoff.
- No application code.  The Alpaca SDK is the axios consumer (`src/lib/alpaca.ts`, Node HTTP adapter).

## Decisions & Trade-offs

- Merge.  1.20.0 hardens runtime option reads against prototype pollution.  `PayloadTooLarge` and `UnprocessableEntity` stay as deprecated aliases of the new RFC 9110 names.
- The XHR change (navigation cancel rejects with `ECONNABORTED` instead of resolving status 0) does not apply.  This repo does not use the browser XHR adapter.
- `PLAN.md` and phase docs are intentionally untouched.  This bump does not change product scope or a phase design.

## Verification State

- Required checks on the PR head before this docs commit: `verify` pass, `gitleaks` pass, `check-pin` pass (Usage-Monitor main is on congress-trading-shared v2.7.1, matching Congress.Trade provenance `5084afb`).
- No new local test run for the docs-only follow-up.  The lockfile itself was already covered by `verify-hosted`.

## Next Steps & Blockers

- Squash-merge when the docs commit is green.  Merging to `main` is the ship path.  Do not Coolify-deploy by hand.  Weekday RTH latch still applies.  Today is Sunday, so the latch should not hold the image.

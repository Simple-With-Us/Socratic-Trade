# Rollout: MAE/MFE Persistence (2026-06-21)

## Summary

Wired persistence for Maximum Adverse Excursion (MAE) and Maximum Favorable
Excursion (MFE) on closed lots and fill_events. This is additive storage only —
no trading logic or P&L accounting was changed. The excursion math
(`calculateExcursions`) already existed in `learning-loop.ts`; this change
adds the missing plumbing to persist those values into the database and stamp
them onto `ClosedLot` objects.

## Why

Excursions were computed ephemerally on every post-mortem run (hitting Yahoo
Finance OHLCV on each call) but never written back to the DB. Historical
analysis panels cannot efficiently re-fetch OHLCV on every page load. Persisting
mae/mfe once (in the background post-mortem path) makes them cheaply available
for future dashboards and learning-loop analysis.

## Files

- `src/lib/performance.ts` — added `mae?: number` and `mfe?: number` to the
  `ClosedLot` interface (additive).
- `src/lib/learning-loop.ts` — added `enrichClosedLotsWithExcursions(lots, compute?)`
  exported async function; imported `ClosedLot` type.
- `src/lib/db.ts` — guarded migration adds `mae REAL` and `mfe REAL` columns to
  `fill_events`; added `upsertFillExcursions(id, mae, mfe, userId?)` and
  `upsertFillExcursionsByKey(accountNumber, symbol, filledAt, mae, mfe, userId?)`.
- `src/lib/post-mortem.ts` — imports enrichment + persist helpers; added
  fire-and-forget `persistExcursionsBackground(accountNumber, source, userId)`
  called at the end of `generateReflectionSummary`; never blocks the LLM path.
- `test/mae-mfe.test.ts` — new test file: 6 tests covering enrichment (mock
  fetcher stamps mae/mfe, null fetcher leaves lot unchanged, missing fields
  skipped, cache de-duplication), and DB round-trip (upsertFillExcursionsByKey
  and upsertFillExcursions both write and read back correctly).

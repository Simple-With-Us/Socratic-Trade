# 2026-11-10 ST-2789 — strict nonce CSP (report-only by default)

## 1. Context & Objective

Live CSP was report-only and still allowed `'unsafe-inline'` and `'unsafe-eval'` on `script-src`, so enforcing it would not have stopped an injected script.  This change replaces that starter policy with a per-request nonce so a later env flip can enforce the same string.  Production is not flipped to enforcing here.

Linear: [ST-2789](https://linear.app/simple-with-us/issue/ST-2789/csp-is-report-only-with-unsafe-inlineunsafe-eval-on-the-live-site).

## 2. Changes Made

Middleware mints a 128-bit Web Crypto nonce on every request and, when `CSP_ENABLED` is truthy and `CSP_POLICY` is unset, forwards it as `x-nonce` plus a `Content-Security-Policy` request header.  Next.js reads that request header and nonces its own framework scripts.  The browser-facing header stays `Content-Security-Policy-Report-Only` unless `CSP_REPORT_ONLY` is explicitly `0`, `false`, `no`, or `off`.

Default `script-src` is `'self' 'nonce-<n>' 'strict-dynamic'`.  `'unsafe-eval'` is added only when `NODE_ENV` is `development`.  There is no `'unsafe-inline'` on scripts.  `style-src` keeps `'unsafe-inline'` because Tailwind v4 and Next (including styled-jsx) emit inline styles that are not bound to this nonce.  A nonce or hash in `style-src` would also make browsers ignore `'unsafe-inline'`.  `report-to csp-endpoint` sits next to `report-uri /api/csp-report`, with `Reporting-Endpoints: csp-endpoint="/api/csp-report"`.  `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`, and `object-src 'none'` stay.  `worker-src 'self' blob:` covers the Sentry Replay worker, which does not inherit `strict-dynamic`.

`CSP_POLICY`, when set, still replaces the whole directive string.  In that mode the nonce is not forwarded, so a custom policy is not mixed with a nonce the policy does not name.

### Inline script inventory

Grep of `app/**/*.tsx` for `<script` and `next/script`:

- `app/layout.tsx` — theme bootstrap (`themeInitScript`) and the PWA unregister script.  Both are constant, so the dynamic policy allows them by sha256 (`LAYOUT_SCRIPT_HASHES`).  The layout does not read a nonce.
- `app/welcome/page.tsx` — JSON-LD (`application/ld+json`).  A JSON-LD element is still a script for CSP.  It is covered by the hash list stamped from the prerendered HTML, not by a nonce.
- No `next/script` imports under `app/`.
- Sentry (`instrumentation-client.ts`, `withSentryConfig`) and Datadog RUM (`DatadogRumBoot`) are bundled modules, not extra script tags.  Next nonces the bundles from the request CSP.
- Cloudflare Web Analytics is not shipped in this repo.  An edge-injected beacon is a parser-inserted script, so it cannot receive this nonce and will show up in `/api/csp-report` until that injection is removed.

### Rendering trade-off

A nonce is per request, and Next can only stamp it while a page is rendered dynamically.  The root layout does not call `headers()` and does not export `force-dynamic`, so it does not drag the rest of the tree into dynamic rendering.

`/welcome`, `/privacy-policy`, and `/terms-and-conditions` keep `revalidate = 3600`.  Their CSP is not a nonce.  `scripts/stamp-csp-static-hashes.mjs` runs at the end of `npm run build`, hashes every inline script in that build's prerendered HTML, and writes the list into `.next/server/middleware.js` in place of the `__ST2789_STATIC_HASHES__` sentinel.  The HTML is not rebuilt, so the hashes match the files just produced.  That policy has no nonce and no `strict-dynamic`, because the cached `<script src>` tags do not carry a nonce and `strict-dynamic` would ignore `'self'`.  The header name still follows `CSP_REPORT_ONLY`, so the env flip enforces these pages too.

Until that stamp exists (unit tests, and `next dev`), those three routes stay on `Content-Security-Policy-Report-Only` with `script-src 'self' 'unsafe-inline'`, even when `CSP_REPORT_ONLY=0`.  Enforcing that fallback would allow inline scripts on purpose, which is not the nonce policy.

Routes that render per request keep the nonce policy.  `/`, `/login`, `/framework`, and `/mobile` were already `force-dynamic`.  Console and admin shells stay dynamic because they read the session.  A CDN cache of the ISR HTML is safe only because the hash policy does not change per request.  Do not put a nonce on those three responses.

## 3. Decisions & Trade-offs

- No new env vars.  `CSP_ENABLED`, `CSP_REPORT_ONLY`, and `CSP_POLICY` are the only switches.
- Report-only remains the default.  This PR does not set `CSP_REPORT_ONLY=0` in Infisical or anywhere else.
- `style-src 'unsafe-inline'` stays until a style hash pass exists.
- `worker-src 'self' blob:` is included so Sentry Replay does not fail the clean-telemetry bar by itself.  Other third-party script injections still need a report before enforcing.
- Dynamic rendering is limited to routes that already render per request.  The three ISR pages use build-stamped hashes.  Experimental SRI was not enabled.  It hashes external files, and Next still inlines the flight payload.

Vitest: 8 files, 98 tests, all passed.  ESLint: 0 errors, 867 pre-existing warnings.  `NODE_OPTIONS=--max-old-space-size=4096 npm run build` completed and `scripts/stamp-csp-static-hashes.mjs` wrote hash lists for `/welcome`, `/privacy-policy`, `/terms-and-conditions`, the console shells, `/access-denied`, `/how-it-works`, and `/strategy`.  The route table marks welcome, privacy, and terms as ISR (`1h` revalidate, `1y` stale-while-revalidate).  `/login` stays dynamic.

A local `next start` with `CSP_ENABLED=1` served those ISR pages with `Cache-Control: s-maxage=3600, stale-while-revalidate=31532400`.  The report-only policy had no nonce and no `strict-dynamic`, and every inline script's sha256 was in `script-src` (5 on `/welcome`, 4 on each legal page).  Two `/welcome` responses carried the same policy.  `/login` stayed `private, no-cache, no-store`, used `strict-dynamic`, and a second request minted a different nonce.  `/console` matched its four inline scripts under the stamped hash policy and `s-maxage=31536000`.

The built middleware still reads `process.env.CSP_ENABLED` and `process.env.CSP_REPORT_ONLY` at request time.  `CSP_REPORT_ONLY=0` enforces the nonce policy on dynamic routes and the stamped hash policy on prerendered routes.

## 5. Next Steps & Blockers

1. After this deploys, watch CSP reports.  The collector is `POST /api/csp-report` (also `GET` 204).  Each accepted report logs one line: `[csp-report]` plus a short JSON object with `violated`, `blocked`, and `document` (truncated).  Read the container logs for that prefix.  Do not treat a quiet hour as clean.  Exercise login, console, welcome, privacy, and terms.
2. Expect a report if Cloudflare injects Web Analytics.  That beacon is not in this repo and will not carry the nonce.  Remove the injection or accept the violation before enforcing.
3. Enforce with no code change, only after those reports are clean: set `CSP_REPORT_ONLY=0` (also accepted: `off`, `false`, `no`) in Infisical for this app and let the next boot pick it up.  Leave `CSP_ENABLED` on.  Do not set `CSP_POLICY` unless you intend to replace the nonce policy entirely.
4. Do not enforce as part of merging this PR.

## 6. Zero-Code Findings

Cloudflare Web Analytics and any other zone-injected script are outside the HTML this app renders.  `strict-dynamic` will not allow them.  That is the main report to look for before the env flip.

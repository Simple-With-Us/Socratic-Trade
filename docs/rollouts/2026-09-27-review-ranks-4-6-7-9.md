## 2. Changes Made

### 2.1 Rank 4 — equal-risk sizing (in-house, money path)

`policy.tuning.maxPositionRiskPctOfEquity` caps the DOLLAR risk a single position may carry, so
`size = risk budget ÷ stop distance`.

The review's motivating shape: on Alpaca Paper, 4 lots accounted for 70% of the account's
-$185.93, and Insider-Accumulation was positive in **percent** (+0.14%/lot) while negative in
**dollars** (-$6.99) purely because its losers were the bigger positions.  Everything upstream in
`applyDeterministicSizing` sizes to a **notional**, so a name whose stop sits further from entry
silently risks proportionally more.  A notional cap structurally cannot see that; a dollar-risk cap
can.

- `resolveStopDistancePct` (`strategy-risk.ts:441`) prefers the stop the order will actually carry
  (`proposal.stopPrice` vs `referencePrice`), then `riskRules.stopLossPct`, then the same shared
  `STOP_PLAN_FALLBACK_STOP_PCT` the rest of the codebase uses.  It never returns 0 for a configured
  stop, because a 0 distance makes `budget ÷ fraction` infinite and would silently disable the cap.
- Applied before the ADV cap, and **re-asserted after the bracket-minimum raise** (`strategy-risk.ts:924`).
  The bracket raise exists only so Alpaca can place a native whole-share bracket — a convenience, not
  a risk requirement — so it must not push an order back over the budget.  The cost is that such an
  order loses its broker bracket and places unbracketed, which is the right way round.
- **Loses, loudly, to a hard broker minimum**, with a `sizing_equal_risk_breached_by_broker_minimum`
  audit event.  Only reachable when the budget is itself smaller than a broker minimum, which is a
  misconfiguration worth surfacing rather than a routine trim.
- Announced in the order rationale and via `sizing_equal_risk_capped`, matching the `volTargetNote` /
  `thesisSizeMultipliers` convention: silent shrinkage is indistinguishable from a bug in the log.

A design point the tests forced: the first application deliberately does **not** clamp
`effectiveOpeningCap`.  Clamping capacity would also suppress the bracket raise, which would leave the
re-assertion untestable and the interaction untested.  The risk cap is a dollar budget, not a capacity
constraint.

### 2.2 Rank 6 — controlled model-rotation pin (worker, `src/lib/model-rotation*.ts`)

The review could not compare models because the rotation strategy changed three times, so each
model's numbers are tied to a calendar period.  New `src/lib/model-rotation-pin.ts` (pure, no DB, no
module state) plus wiring in `model-rotation.ts`:

- `resolveRotationSeatPin` validates the force half and the weight half **independently**, so a bad
  force does not discard valid weight overrides.  Unknown models, out-of-range weights and malformed
  pins are refused with a receipt (`rejected[]`), never silently producing an empty rotation.
- `weightedRotationPick` gained `weightOverrides`; the floor resolves to the last **positive-weight**
  candidate, so a 0-pinned tail model cannot be resurrected by a float edge, and an all-zero set
  degrades to the learned weights.
- Pinned picks are excluded from the representation ledger by design — "removes exactly" was chosen
  over "every pick counted", because a reversible experiment that corrupts its own weights is not
  reversible.
- `TradingPolicy.rotationPin` added in `types.ts` by the coordinator (the worker did not own that
  file).  Per-policy, which is what keeps the review's alternative — "split models by account" —
  viable, since a policy is already per-account.
- Never silent: a `model_rotation_pin` audit row per run (applied **or** refused), `pinned`/`forced`/
  `pinLabel` on the matching `model_rotation_pick` rows, a `rotationPin` field on the resolve result
  that is absent entirely when unpinned, and a log line on every run it touches.

### 2.3 Rank 7 — honest Red Team scoring (worker, `src/lib/performance.ts`)

- `clusterVetoScenarios` collapses repeat vetoes of the same `symbol+side` within
  `RED_TEAM_DEDUP_WINDOW_DAYS = 7` to the **earliest** veto, keeping its own counterfactual.  7 days
  is the calendar length of the pipeline's own 5-trading-day horizon.
- New `RedTeamEfficacy` fields: `uniqueScenarios`, `duplicateVetoes`, `maturedUniqueScenarios`,
  `medianReturnPct`, `sampleSufficient`, `minUniqueMaturedForVerdict`, `verdict`, `horizon`.  Raw
  `totalVetoes`/`maturedVetoes` keep their pipeline meaning; rates, mean, median, `byModel` and
  `records` now run on the deduped set.  This is the review's "+1.16% headline comes from one vetoed
  PYPL buy at +27.4%" problem: the median now travels with the mean.
- `horizonDisclosureText` reports the configured counterfactual horizon, the median realized
  measurement window, and (when supplied) the approved book's median hold, with `horizonMatched` false
  unless they line up.  The review's complaint was that a 5-day counterfactual was compared against
  3-12 day actual holds; the mismatch is now visible instead of silent.

### 2.4 Rank 9 — SPY feed visibility (worker, `src/lib/benchmark.ts`)

**Root cause diagnosed, not guessed.**  `fetchDailyOHLC` is a 10-source cascade whose per-source
fetchers each do `catch { recordProviderCall(source, {ok:false}); return null; }` — the error is
reduced to a boolean and the message discarded.  When the whole cascade returns null it does **not**
return null: it returns the frozen local EOD cache re-stamped `fetchedAt = now` and
`source = "history-cache-eod-stale"`, plus one `eod_cache_stale` audit row that names no provider.
The bar dates never advance.  The original gate compared the newest close to the **account window's
end**, so a feed frozen alongside a dormant account passed and rendered a flat 0.00% "vs SPY".

Fix: judge staleness against the **wall clock** first, and make the feed facts part of the result —
`status`, `stale`, and `feed` (`lastCloseDate`, `staleDays`, `source`, `fetchedAt`,
`fellBackToStaleCache`) on every return path.  "Stale" can no longer be confused with "0%".

## 3. Decisions & Trade-offs

- **Rank 4 wins over the bracket, loses to the broker minimum.**  A convenience raise must not breach
  a risk budget; a hard broker constraint may, but must say so.
- **Pinned picks excluded from the representation ledger.**  Chosen for exact reversibility; the
  alternative is a one-line flip at `model-rotation.ts:579` and is a deliberate trade, not an oversight.
- **The Red Team's approved-side comparison is exposed, not faked.**  `getRedTeamEfficacy` is
  user-wide with no `accountNumber`, and `listFillEvents` requires one, so the approved leg is
  unreachable without a new query in a file the worker did not own.  Rather than ship a fake match,
  it added an injection point (`options.approvedHoldMedianDays`) and a disclosure block.
- **`BENCHMARK_STALE_GRACE_DAYS` left at 5.**  Weekend/holiday tolerance is load-bearing.

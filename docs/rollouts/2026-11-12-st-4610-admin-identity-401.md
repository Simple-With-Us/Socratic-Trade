# ST-4610 — Admin identity 401 (not 500)

## Context & Objective

`x-admin-token` callers could pass `requireAdmin` but still hit unhandled 500s when `resolveRequestUserId` enforced live-bootstrap identity.  Goal: return a clear JSON 401 for identity failures without loosening auth.

## Changes Made

- Added `IdentityRequiredError`, `identityErrorResponse`, `resolveRequestUserIdOrResponse`, and `resolveRequestUserOrResponse` in `src/lib/request-user.ts`.
- Wired `app/api/**` route handlers to return the 401 body `{ ok: false, error: "verified_identity_required", reason }` when identity resolution fails.
- Added regression tests in `test/admin-learning-ledger-identity.test.ts`.

**Files touched (high level):** `src/lib/request-user.ts`, `app/api/**` (identity guards), `test/admin-learning-ledger-identity.test.ts`, `test/request-user-live-bootstrap.test.ts`, `docs/rollouts/2026-11-12-st-4610-admin-identity-401.md`, `STATUS.md`.

## Decisions & Trade-offs

- Admin token callers still must present verified email under `DB_BOOTSTRAP=live`; no `DEV_USER_ID` / operator fallback.
- Session-revoked and other non-identity errors keep existing throw paths.

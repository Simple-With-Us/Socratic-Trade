# 2026-07-18 — Remove tracked lint/verify artifacts + Codex env config from main (MONET)

## Summary

Deletes 8 machine-specific generated files that were accidentally committed to `main`
(landed via PR #1735) and adds `.gitignore` patterns so they can never be re-tracked.
No app source, test, or runtime code is touched.

Removed (all confirmed unreferenced by any `.ts/.tsx/.js/.mjs/.cjs/.json/.sh/.yml`
source, script, or CI config):

- `error.log` (~8 KB)
- `lint-output.txt` (~104 KB)
- `lint-results.txt` (~100 KB)
- `lint-results.json` (0 B)
- `lint_results.json` (~1.6 MB)
- `eslint-report.json` (~5.0 MB)
- `eslint_test_results.json` (~1.6 MB)
- `.codex/environments/environment.toml` (autogenerated Codex cloud-env config)

That's ~9 MB of generated output removed from the tree.

## Why

- These are eslint / verify-run outputs containing machine-specific absolute paths
  (`/Users/jay/...`). They regenerate differently on every run, so they only bloat the
  repo and create noisy diffs/merge conflicts — Codex flagged exactly these on #1735
  ("Remove generated lint artifacts from the commit"), but they merged anyway.
- `.codex/environments/environment.toml` is marked `# THIS IS AUTOGENERATED. DO NOT EDIT
  MANUALLY` and commits `setup.script = ""`. A tracked empty setup script overrides the
  repo's canonical cloud setup, so fresh Codex environments would skip `npm ci` + the
  Slack-sync hook install (Codex's #1735 review raised this too). Removing it + ignoring
  `/.codex/environments/` lets each environment regenerate/fallback correctly. The
  intentional `.codex/maintenance.sh` and `.codex/setup.sh` stay tracked.

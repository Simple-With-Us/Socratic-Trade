### 1. Vector-db budget defaults (`scripts/eval/rag-census.ts`)

**Before:** `getConfigurationSummary()` defaulted `RAG_INGEST_MAX_TEXTS_PER_DAY` to `1,000,000` and `RAG_PINECONE_MAX_WRITE_UNITS_PER_DAY` to `10,000,000` when the env var was unset. These were stale values from an earlier code version.

**After:** Defaults changed to `20,000` and `200,000` — matching `DEFAULT_INGEST_MAX_TEXTS_PER_DAY` and `DEFAULT_PINECONE_WRITE_UNITS_PER_DAY` in `src/lib/vector-db.ts`. The `numericEnv()` fallback arguments also updated so that when env is present but blank/invalid, the census reports the same value the ingest path will actually use.

### 2. Paid-tier filing cap (`scripts/eval/rag-census.ts`)

**Before:** `SEC_FILING_RAG_MAX_PER_RUN` always fell back to `1` when env was present but blank/invalid, regardless of paid-tier status.

**After:** Added a local `isFreeTier()` helper matching `sec-filings.ts`'s tier logic (`VECTOR_EMBED_BATCH_DELAY_MS <= 5000` = paid). The `numericEnv()` fallback now uses `isFreeTier() ? 1 : 200`, matching `maxFilingsPerRunFromEnv()`.

### 3. Congress sort composite (`app/console/scan/columns.tsx`)

**Before:** `sortValue` for the Congress column only returned `q.senateTrades`. When a quote had only `congressCompositeScore` (no raw trade disclosures), `scan-table.tsx` treated the sort value as missing and sorted it last in both directions.

**After:** `sortValue` now falls back to `q.congressCompositeSignedScore ?? q.congressCompositeScore` when `senateTrades` is absent, so composite-only signals appear in sort order.

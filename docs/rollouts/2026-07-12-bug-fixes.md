# 2026-07-12 — Activity feed coalescing and audit attribution bug fixes

## Summary
Resolved test regressions caused by recent P3 fixes and completed the audit attribution sweep to ensure `connectedAccountId` is properly logged across `broker-protective-stops.ts`.

## Why
- **Test Regressions**: The newly introduced P3 features broke existing assertions:
  1. `test/dashboard-feed.test.ts` started failing because the new feed-storm coalescing logic merged identical "proposal-less" test items into single groups, artificially reducing the expected list lengths (`UNIFIED_FEED_MAX_GROUPS`).
  2. `test/connection-health-routing.test.ts` failed because the recent `DIRECT_NOTIFY_SKIP_SET` addition appropriately silenced dual-logging `storage_warning` events into the `notification_events` table, but the test was still trying to read from `notification_events` to assert the event fired.
- **Audit Attribution**: The MONET 2-3 day activity audit discovered that some automated actions (especially in background jobs and synthetic stops) were failing to attribute the event to the correct account, logging missing `connectedAccountId` values. An earlier sweep covered `strategy.ts` and `synthetic-stops.ts`, but `broker-protective-stops.ts` had a few remaining nested multi-line `audit()` calls lacking the account ID.

## Files
- `src/lib/notifications.ts` (added `storage_warning` to the skip set)
- `test/connection-health-routing.test.ts` (updated to query `audit_events` instead of `notification_events`)
- `test/dashboard-feed.test.ts` (injected distinct ticker symbols into test entries to prevent unwanted coalescing)
- `src/lib/broker-protective-stops.ts` (added `policy.connectedAccountId` to remaining multi-line `audit()` calls around line 543 and 751)

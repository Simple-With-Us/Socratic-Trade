# iOS Performance Audit — 2026-11-21 (ZC)

Seat ZC, lane `zc-ios-ux-perf-audit` (read-only audit; no code changed, no builds run — Swift compile is CI-only in this fleet).  Scope: `ios/SocraticTrade/**`, 41 Swift files, read against the server mobile endpoints that feed them (`app/api/mobile/snapshot/route.ts`, `app/api/mobile/events/route.ts`, `src/lib/dashboard.ts`, `src/lib/db-fills.ts`).  Baseline context: `ios/CLAUDE.md` and `docs/reviews/2026-08-31-grok-full-stack-audit.md`; `git log --oneline -30 -- ios/` checked so already-fixed items are not re-filed.

## Already fixed by recent work (not re-filed)

- Duplicate-command `Dictionary(uniqueKeysWithValues:)` crash — now folded deterministically (`MobileStore.swift:84-95`).
- Keychain re-read churn on restore — ST-4596 reads once per restore (`48525b29fd`).
- Snapshot/SSE 5xx retry dedupe and bounded GET retry budget — #5142, #5175 (ST-4633); retry ladders are bounded and non-compounding (`MobileAPIHTTPRetryPolicy.swift`, max 3 requests per refresh).
- Resume-gate held handles — ST-4605.
- Login `preconditionFailure` at the OLD line 638 — moved, but still present: see X1.

### 2. Observation graph and re-renders

| # | Finding | Impact | Effort | Evidence | Status | Fix |
|---|---|---|---|---|---|---|

### 3. Networking

| # | Finding | Impact | Effort | Evidence | Status | Fix |
|---|---|---|---|---|---|---|
| N1 | Every SSE payload event triggers a FULL snapshot reload (`scheduleReload` -> `load()`).  A single approve does: `submit()` awaits `load()` itself, then the `mobile.command`, `dashboard.order`, and run events each schedule another full reload (coalesced only while one is in flight).  One user action can cost ~3 full snapshot downloads (see N2 for how fat each one is). | H on cellular/battery during active runs; server cost too | M | `MobileStore.swift:937-941` (onEvent -> scheduleReload), `:1046-1055` (submit awaits load), `:1420-1434` (coalescing loop); event types forwarded by the server: `app/api/mobile/events/route.ts` (mobile.command + every dashboard.* type) | Open | Handle events by type: debounce reloads (trailing 2-5 s) per event class; for `mobile.command` patch the local `recentCommands` entry instead of refetching everything; keep the full reload for unknown/dirty events.  The coalescing already prevents parallel stampedes — this is about total bytes and decode churn. |
| N2 | The snapshot payload re-downloads the FULL per-account, per-source fill ledger on every reload — `listFillEvents(..., undefined)` is the unbounded ASC query (grok 2026-08-31 P1 `79daff38`, still open) — plus `latestScan`, benchmark series, 100 notification rows, and the audit feed.  The phone shows at most 20 fills (Activity) and the P&L numbers are already server-computed. | H (bytes + decode CPU + battery; grows forever with trading history) | M (server-side) | Server: `src/lib/dashboard.ts:1096-1097` (liveFills/paperFills with `undefined` limit), `src/lib/db-fills.ts:413-436` (default UNBOUNDED); payload assembly `app/api/mobile/snapshot/route.ts` (`performance: withMobileEquityCurveCompat(...)`); iOS decode `MobileModels.swift:806` (`fills`), display cap `ActivityView.swift:537-539` (prefix(20)) | Open (server-side; also flagged by grok for web) | Bound fills in the mobile payload: the feed needs newest ~50, and lot-based metrics are precomputed server-side.  Biggest single win for data volume; fixes the worst half of O4 at the same time. |
| N3 | SSE-drop fallback double-fires work: every stream failure both schedules a full snapshot reload AND lets the reconnect loop retry with backoff (1.5x to 30 s).  During an outage, each reconnect failure adds another snapshot attempt (with its own 2-attempt, 45 s-timeout ladder).  Bounded, but two ladders overlap. | M during outages (radio wake + server load) | S | `MobileStore.swift:949-976` (error path: scheduleReload at `:961-965` plus backoff loop) | Open | Reload on the first drop only (latch reset on successful reconnect), or skip the manual reload entirely and let the reconnect's `onConnect` trigger one refresh. |

## Priority order (if only five things get fixed)

1.  O1 + O2 — @Observable migration and the per-line SSE objectWillChange: kills the whole-tree re-render amplifier everything else rides on.
2.  N2 — bound the fills in the mobile snapshot payload (server-side; also closes grok `79daff38` for the phone).
3.  N1 — event-typed/debounced SSE reloads instead of full snapshot per event.
4.  S2 — stop gating the login screen behind a 401-ing snapshot probe (cold-start seconds).
5.  L3 — cached ticker-logo loader (first-paint and scroll quality on every list).

Verification for any fix lane: hosted `ios-build` (unsigned build + simulator XCTest) is the only compile gate; perf claims should be evidenced with `os_signpost`/Instruments-in-CI or before/after byte counts from `scripts/fetch-prod-ops-snapshot.sh`-style probes, not local xcodebuild.

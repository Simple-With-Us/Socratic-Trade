## 1. Mission A — top-bar diagnosis

### 1.1 Current anatomy (phone, viewport < 640 CSS px = every iPhone portrait)

The sticky top bar (`shell.tsx:255-259` `.con-topbar`) stacks four rows before any content:

```
Row 1  RealityBanner        full-width, py-1.5          (paper / no-account only)   ~30pt
Row 2  [ScopeSelector ——— flex-1 ———][StateChip]        basis-full row              ~44pt
Row 3  [ .......... empty .......... ][🔍][🔕51][👤][⚡][⃠]  w-full justify-end row   ~44pt
Row 4  MobileFreshnessBar   full-width                   ~26pt
                                                             ChromeBar rows 2-3 sit in
                                                             one flex-wrap container
                                                             (py-2 + 6pt gap ⇒ ~110pt)
Total ≈ 166pt ≈ 19% of an 852pt iPhone 16 viewport.
```

### 1.2 Width math at the iPhone 16 base (393pt)

Inner width of the ChromeBar container = 393 − 24 (`px-3` × 2) = **369pt**.

- **Row 2:** the phone `StateChip` is the unboxed stacked form (`chrome.tsx:313-331`: "Autopilot" over "market closed", ~90-95pt with dot + `px-1.5`).  The `ScopeSelector` wrapper is `flex-1 min-w-[120px]` (`chrome.tsx:220`), so the trigger stretches to 369 − 95 − 6 ≈ **268pt ≈ 68-72% of the row** — exactly the ~70-75% the owner circled.  The label only needs ~150-165pt ("Alpaca Paper — MFK9" at `--con-fs-sm` semibold); the remaining ~100pt is empty box.
- **Row 3:** five controls, each ≥44×44 under the coarse-pointer floor (`console.css:431-460`): search 44 + bell 44 + avatar 44 + ⚡ 44 + STOP ~46 = ~246pt including gaps, right-aligned by `justify-end` (`shell.tsx:474`) — **~120pt (a third of the row) dead on the left**.

### 1.3 Root cause, precisely

1. **The row split.** `shell.tsx:453` puts `ScopeSelector` + `StateChip` in a child with `basis-full` (phone only), and `shell.tsx:474` puts the five action buttons in a second child with `w-full … justify-end`.  The parent (`shell.tsx:451`) is `flex-wrap` below `sm`, so phones hard-wrap into the two unbalanced rows.  Above `sm` both children become `sm:contents` and everything shares one row — which is why the bar looks fine on iPad/desktop.
2. **The stale stretch.** `chrome.tsx:220` `flex-1` on the scope wrapper.  The comment at `chrome.tsx:213-219` documents the original single-row design: the scope "absorbs exactly the space left by the fixed-width chrome controls (state chip, avatar, run-once, run-state)".  After the two-row split (comment at `shell.tsx:446-450`), avatar / run-once / run-state are **no longer in that row**, so `flex-1` no longer "absorbs the leftover next to the icons" — it stretches the picker across a whole row it no longer shares.  This is the single line that turned a balanced bar into the owner's screenshot.
3. **Aggravators.** (a) The last-4 suffix is `shrink-0 whitespace-pre` (`chrome.tsx:233`) — the em-dash suffix never truncates, only the label does, so the trigger cannot shrink below label+suffix without clipping text; combined with `flex-1` the button just gets wide, never narrow.  (b) `RunStateButton`'s text label is `display:none` below 640px (`console.css:515-522`), so STOP is icon-only on the phone — the most consequential control on the bar has no word.  (c) The `RealityBanner` row only exists for paper/no-account, which is why the owner (paper) sees three chrome rows where a live account sees two.

Layout priority order today: STOP and every icon are `flex-shrink: 0` (`console.css:468-472`, `.con-stop-btn` `:499-505`) → StateChip's words are `whitespace-nowrap` (`chrome.tsx:325-327`) → the scope's ` — LAST4` is `shrink-0` → only the scope's label `truncate` flexes.  So the bar already has a correct shrink order; it simply never runs, because the wrap gave the scope a row of its own.

### 1.4 Three redesign options (ordered by recommendation)

All options are phone-only (`< 640px`) changes; the `sm:` one-row desktop/iPad bar is untouched, so wide-window behavior cannot regress (see §1.5).

#### Option 1 (RECOMMENDED) — one control row + overflow menu · effort **M**

Collapse rows 2-3 into a single row; keep banner and freshness rows.  Packing (primary):

```
┌──────────────────────────────────────────────────────────┐
│ PAPER TRADING • broker-provided practice account         │  banner (unchanged)
├──────────────────────────────────────────────────────────┤
│ [Alpaca Paper — MFK9 ∨] [● Autopilot]  ←slack→  [🔍][🔕51][⃠] │  ONE 44pt row
├──────────────────────────────────────────────────────────┤
│ Fresh · 🛡 Deployed today: $0.00                         │
└──────────────────────────────────────────────────────────┘
Overflow ⋯ does not exist as a 6th button in the primary packing; instead the
avatar button doubles as the overflow trigger (menu: Search / Run Once / theme /
sign out / Admin) — OR see variant below. Scope keeps flex-1 min-w-0 and now
genuinely absorbs only the true leftover, its intended PR #1708 behavior.
```

Variant packing (same widths, owner's call): `[scope][● Autopilot][🔔51][⋯: Search·RunOnce·Account][⃠ STOP]` — keeps the bell glanceable badge direct and puts search one tap deep.

- Concrete changes:
  1. `shell.tsx:453` — drop `basis-full`; let `ScopeSelector` + `StateChip` sit inline with the action cluster on phones (delete the phone-only second row at `:474-493`; its children move up; `sm:contents` wrappers simplify away).
  2. `chrome.tsx:220` — keep `flex-1 min-w-[120px] min-w-0` (now correct again) and add a phone-only growth cap so it can never re-hog: `max-w-[46vw] sm:max-w-[300px]`.
  3. `chrome.tsx:313-331` — phone `StateChip` collapses to dot + state word only ("Autopilot"); the mode ("market closed") moves to the button `title` and stays in the ControlSheet + the Home STRATEGY card pill, which already shows "Autopilot · market closed" (screenshot row 2).  Saves ~35pt.
  4. New ~40-line `BarOverflowMenu` in `chrome.tsx` (reuse `useAnchoredMenu`, right-aligned, same pattern as `UserMenu` `:893`): rows = Search (dispatches `CMDK_EVENT`), ⚡ Run Once (`RunOnceButton` logic hoisted to a callable), then the existing `UserMenu` contents (identity, theme, Admin, sign out).
  5. Direct on the row: `CommandPaletteTrigger`, `NotificationInbox`, `RunStateButton`.  **STOP stays exactly where it is — far right, one tap, zero ceremony.**  Autopilot state stays visible at all times (chip, word-only).
- Width ledger @393 (369 inner): STOP 46 + bell 44 + search 44 + chip ~60 + 4 gaps 24 = 218 ⇒ **scope = 151pt** — fits "Alpaca Paper — MFK9" (~150-165) with at most a 1-2 char label clip; truncate + `shrink-0` suffix handle the rest.  @360 (336 inner): scope 118 — lower phone gap to `gap-1` or trim chip padding.  @320 (SE, 296): hide the chip word below ~360px (dot-only state indicator) so nothing overflows.  The overflow menu is the "one more future control" slot — new actions go inside it for free.
- Keeps visible: STOP, autopilot state, notifications badge, search.  Moves deeper: Run Once (also remains the Home hero CTA), avatar/theme/sign-out (low-frequency).  Chrome height drops from ~166pt to ~116pt (−50pt every screen, paper account).
- Risks: `test/e2e/header-menus.spec.ts:39-42` exercises the scope dropdown — mechanics unchanged, only trigger width.  Mobile-chrome visual baselines are not run (desktop-only, `test/e2e/visual.spec.ts:5,26`), so no snapshot churn.

#### Option 2 — deliberate two-line bar with labeled run controls · effort **M**

Choose this if the owner wants words, not icons, on the two most consequential controls.  Row 2 = status (scope hugs content, full chip with mode, bell, overflow); row 3 = a 50/50 44pt action split that deliberately spends the dead left space:

```
│ PAPER TRADING • broker-provided practice account              │
│ [Alpaca Paper — MFK9 ∨] [● Autopilot · market closed] → [🔕51] │
│ [   ⚡ Run Once   ] [        ⃠ STOP AGENT           ]          │  labeled, 50/50, 44pt
│ Fresh · 🛡 Deployed today: $0.00                              │
```

- Changes: `chrome.tsx:220` phone variant becomes `flex-none max-w-[62%]` (picker hugs content — the owner's accepted option (a)); restore `.con-run-state-label` on phones (`console.css:515-522` remove the `display:none` block) and un-hide the labeled `RunOnceButton` (`shell.tsx:480-491`); row 3 becomes `flex gap-1.5` with both buttons `flex-1`.  No overflow menu needed — avatar and search stay as-is.
- Fixtures the "STOP icon-only" ambiguity (W2 below) and puts Run Once one tap away with a label.  Cost: keeps today's two control rows (~110pt) — no vertical savings; at 320-360pt the labeled pair still fits (each ≥140pt).

#### Option 3 — smallest rebalance, keep two rows, no menus · effort **S**

Pure width fixes, zero information architecture change (owner's options (a)+(b)):

```
│ [Alpaca Paper — MFK9 ∨] [● Autopilot · market closed]         │  scope capped, hugs content
│ [ ⚡ Run Once ] ·························· [🔍][🔕51][👤][⃠]   │  labeled CTA left, icons right
```

- Changes: `chrome.tsx:220` add `max-w-[62%]` under `sm` (two-class change); `shell.tsx:474` row gains a leading labeled `RunOnceButton size="sm"` before the spacer (delete the `sm:hidden` icon-only duplicate at `:489-491`, keep one button that is labeled on all sizes).  Left space now carries a real control; nothing moves, nothing hides.
- Zero regression surface (same rows, same controls, one duplication removed); does not fix the vertical cost or the STOP icon-only ambiguity.

**Recommendation: Option 1.**  It is the only one that produces a clean single control line at 393pt, returns ~50pt of screen per view, restores the scope selector's intended "absorb only the leftover" behavior, and gives future controls a home (the overflow) without another redesign.  Option 2 is the right fallback if the owner tests Option 1 and misses the words on STOP/Run Once.  Option 3 is the one-evening stopgap.

### 1.5 Dynamic-type / landscape / wide-window regression check

- **Web ≥640px (iPad, iPhone landscape 667-740pt, Mac):** untouched by every option — all changes are gated below `sm`; the `sm:flex-nowrap sm:overflow-x-auto` single row (`shell.tsx:451`) and the scope's `sm:min-w-[190px] sm:max-w-[300px]` caps (`chrome.tsx:220`) stay.
- **Text scaling (iOS Safari page zoom / Dynamic Type in apps using web content):** the scope trigger already truncates (`chrome.tsx:232`) and the chip words are `whitespace-nowrap`; Option 1's word-only chip truncates less, not more.  The coarse-pointer 44×44 floor (`console.css:431-460`) covers the new overflow trigger if it gets the `con-bar-ctl` class (spec'd above).
- **Native wide-window work (context, not affected):** the SwiftUI app's adaptive systems — `TabBarCapacity` (`MobileControlView.swift:114-125`, compact 4 → up to 8 by `onGeometryChange` at `:509-513`), `ContentColumns` card flow (`AppComponents.swift:1231`, columns by measured width in `SnapshotScaffold` `:769-773`), `AdaptiveWideSheet` (`AppComponents.swift:1651`), and Dynamic-Type-ceilinged chrome fonts (`AppTypography.swift`, `AppChromeFontScaling`) — are all native-side and independent of the web bar; no option touches them.

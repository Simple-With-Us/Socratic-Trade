## Summary

The production boot chain and the deploy-latch machinery are fundamentally sound: the exit-code contract is honored in the container (bash supervisor translates spontaneous clean exits to 40, both node wrappers translate signal deaths to 128+N with no `process.kill(process.pid)` re-raise, and the exec chain invokes `node_modules/.bin/next` directly with no `npm run`), secret handling is clean across every reviewed script (no bare `infisical secrets`, no `set -x`/`curl -v`, no cat of `~/.secrets/global-api-keys`, tokens only ever in 0600 curl config files or headers), and the ASCII `$VAR`-adjacency trap is absent (zero matches on the fatal pattern; the flagged non-ASCII bytes are all non-adjacent, so nothing breaks today).  The concrete problems are: (1) `rth-deploy-drain.sh` exits 0 when it could not nudge Coolify, so a failed after-close drain is a green CI job with no alert (the silent-freeze class this machinery exists to catch), and the gh-redeliver path cannot work with GITHUB_TOKEN, so the drain depends entirely on an unverifiable `COOLIFY_DEPLOY_WEBHOOK_URL` secret; (2) the deploy-freshness watchdog has no RTH-latch awareness and will page/alert on every deliberately latched weekday-RTH merge at the 1h mark; (3) `runner-availability.sh` still publishes `VERIFY_RUNNER_STATE` for the retired Mac self-hosted runner / pm2 `trading` lane, and `scripts/ops/fleet-watchdog.service` still references the deleted `fleet-site-watchdog.sh`; (4) the Mac-side litestream restore/drill scripts + `litestream.yml` still describe the dead R2 replica (`region: auto` is R2-only), while the live replica is B2.  Twelve findings total (1×P1, 2×P2, 5×P3, 4×P4).

## Findings

**1. P1** | **rth-deploy-drain.sh exits 0 when it cannot nudge — a failed drain is silently green** | `scripts/rth-deploy-drain.sh:136-139` (`if [ "$nudge_ok" -eq 0 ]; then log "could not nudge Coolify..."; exit 0; fi`), wired by `.github/workflows/rth-deploy-latch.yml:66-71` (drain job runs the script; a 0 exit = job success).  What's wrong: the scheduled after-close recovery job reports SUCCESS even when no nudge happened.  In practice the gh-redeliver path (`rth-deploy-drain.sh:105-125`) almost always fails with GITHUB_TOKEN (it lacks `admin:repo_hooks`; the script itself logs "GITHUB_TOKEN often cannot write hooks"), so the only working path is the `COOLIFY_DEPLOY_WEBHOOK_URL` secret (`:127-134`) — if that secret is unset, the drain can never nudge and always exits 0.  Alerting is then blind: the freshness watchdog's Slack de-dupe (`alert-deploy-freshness.sh:110-117`) and Sentry's [workflow, branch] fingerprint (`sentry-ci-report.yml`, `scripts/sentry-ci-report.py`) group the earlier staleness into one alert, so after the first page nothing new fires; prod can stay behind for days with every automation green — the 2026-08-06 silent-freeze class.  Suggested fix: `exit 1` (fail the job → Sentry pages) when `nudge_ok=0`, and fail loudly at startup if neither a gh hook nor `COOLIFY_DEPLOY_WEBHOOK_URL` is available.  Effort S.

**2. P2** | **Deploy-freshness watchdog pages STALE on deliberately RTH-latched merges** | `scripts/alert-deploy-freshness.sh:202-217` (page when oldest undeployed ≥ 3600s; no RTH awareness), `.github/workflows/deploy-freshness.yml` (cron every 20 min; job fails → Sentry error + failed cron check-in), vs `.github/workflows/rth-deploy-latch.yml` + `Dockerfile` (`RUN tsx scripts/assert-rth-deploy-latch.ts` before `npm ci`).  What's wrong: the 2026-08-18 latch intentionally refuses weekday-RTH image builds, so a 10:00 ET merge is legitimately undeployed until the 16:00 close; the 2026-08-06 watchdog cannot distinguish "latch refused the build" from "webhook silently died" and will exit 3 + page/alert at the 1h mark for every weekday-RTH merge (then the 21:20 UTC drain "resolves" it).  False pages in exactly the class the watchdog exists for train agents/humans to ignore real ones.  Suggested fix: have the workflow/script treat a latched weekday-RTH gap as in-flight (e.g., compute `isMarketOpen` via the latch's own `market-calendar` module and pass a flag, or skip the stale verdict inside the RTH window on weekdays).  Effort M.

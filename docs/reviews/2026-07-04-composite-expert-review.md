# Socratic Trade — Composite Expert Review (Fable + Monet)

*Merged from Fable's ~209-item panel and Monet's 147-item panel by Monet, 2026-07-04.*

This document integrates two independent expert-panel reviews of the same Socratic Trade codebase, honoring the same product philosophy: real trading at the owner's accepted risk, guardrails as overridable advisory preferences ("agent decides, logs everything"), receipts as the control plane, and no paternalism / no paper-default. Nothing here re-paternalizes; every enforcement is an owner-adjustable preference with an honest receipt.

## How to read this

Every item carries a source tag: **[Both]** = independently surfaced by BOTH panels (the strongest signal — treat as highest-confidence, do first); **[Fable]** = unique to Fable's panel (Socratic-refocus, receipts-honesty, security/ops resilience, doctrine ledger); **[Monet]** = unique to Monet's panel (classic-ML/quant technique, RAG mechanics, statistical rigor, UI craft). Each item is written as `**<title>** [tag] — <gap + why>; **How:** <technique + file refs>; **[impact / effort]**`. File refs and `tNN` cross-refs are preserved from the originals; where both panels cite the same code from different angles, both refs are kept. Sections are ordered high→low impact within each dimension.

## Executive summary

**Convergence — what BOTH panels independently flagged (the highest-confidence critical path):**

1. **Episodic/decision memory is write-only.** Both found the vector store's decision cases are written but never retrieved at decision time (Fable: `strategy.ts:513` filters memory out of every retrieval; `indexSocraticDecisionMemory` runs once at creation, `strategy.ts:836`. Monet: the `findRelevantExperiences`/`upsertExperiences` the design references simply do not exist). The single highest-leverage decision-quality lever is dark — "a trading mind with memory" that cannot remember.
2. **The per-model learning loop is recorded but never closed.** `proposedByModel` is persisted and shown on the approval card, yet neither panel found any code scoring realized outcomes *by model*, no randomized/bandit assignment makes the comparison causal, and nothing routes toward the stronger model — the highest-leverage decision variable with a wide-open loop.
3. **Reflection is one opaque per-account blob** injected into every Bull prompt regardless of today's regime; both panels want it decomposed into structured, regime/thesis-conditioned, retrievable lessons (Fable §1.41/§3.11; Monet A2/B21/C7).
4. **The Bear (Red Team) is unmeasured and under-informed:** its vetoes never enter the counterfactual pipeline (both), it argues from less evidence than the proposer, and Fable additionally caught the Bear's strict schema silently stripping `confidenceScore` — a live money-path bug that kills the approval-time debate trigger and degrades sizing to neutral 50.
5. **Learning statistics are horizon- and survivorship-dishonest:** both flagged the single fixed 5-day horizon mismatched to real holds, calendar-day (not trading-day) horizon arithmetic, and survivorship bias in matured-outcome joins / the IC universe.
6. **Point-in-time / look-ahead integrity is certified only per-module:** both want it certified end-to-end (macro vintages, RAG as-of, horizon days, amended-filing supersede, backfill join rules) with a single leakage certificate gating auto-apply.
7. **RAG *consumption* is the ceiling on an excellent RAG stack:** both independently found retrieved chunks reach the LLM as a bare blob with provenance stripped, retrieval hard-scoped to one symbol (no cross-symbol/thematic recall), and the richest sources (earnings transcripts, news, macro) retrieved-for but never ingested.
8. **Regime handling is brittle and under-powered:** both found the classifier ignores credit spreads/VIX-term-structure/breadth it already fetches, and gates couple to regime *strings* by substring match — fix with a typed enum + numeric severity, then build graduated de-risking on top.
9. **Prompting robustness and cost converge:** both want a cross-family Bear + non-zero adversary temperature, failover/truncation parity across all LLM roles (not just the Bull), prompt-cache restructuring, self-consistency / model-disagreement as measured uncertainty, and scout-then-analyst staging with agentic on-demand evidence tools.

**What Fable uniquely contributed:**

10. **The Socratic decision-memory loop closures** — the outcome writer, coaching-becomes-durable-learning (kill the silent `slice(-20)`), non-actions as first-class case files, the reversal-trigger invalidation watcher, the doctrine version ledger, framework-proposal *actuation* diffs, the decision-trace inspector, and escalation-as-conversation.
11. **Receipts-honesty security + statistical-honesty + operational-resilience** — injection-attempt detection as a receipt, trust tiers, evidence-age/provenance rendering, tamper-evident audit chaining, the override-lane default-on-execute exposure, Wilson-CI "insufficient evidence" verdicts, the doctrine regression harness as the framework-acceptance test, and durability receipts (SQLite↔Pinecone reconciliation, durable due-jobs, restore drills, crash/reconciliation receipts, keep-awake posture). Under "receipts are the only control," these are correctness-critical, not polish.
12. **Market-microstructure depth** — the halt/LULD feed with stop-suppression receipts, ADV-as-today's-cumulative-volume, marketable-limit spread scaling, paper-fill touch-test realism, and per-regime doctrine playbooks.

**What Monet uniquely contributed:**

13. **Classic-ML/quant rigor and UI craft** — self-consistency/ensembling, structured-output repair + runtime schema validation, HyDE + evidence-derived multi-query + rerank/MMR/contextual-retrieval mechanics, overlap-aware IC standard errors + Deflated-Sharpe/PBO/CPCV multiple-testing correction, hierarchical partial pooling + exploration/IPS de-biasing, volatility-targeting + fractional Kelly + portfolio-heat + factor-crowding aggregation + joint portfolio construction, and a deep console upgrade (SSE streaming, `lightweight-charts`, accessible tooltip/popover primitive, command palette, live risk-utilization board, approval-card full provenance, alert center).

## A. Memory & learning

### High impact

**Retrieve episodic decision memory (closest historical analogs) at decision time** [Both] — Decision vectors are WRITTEN (`strategy.ts:836`) and NEVER read; the only strategy retrieval filters docType to filings (`strategy.ts:513-517`), so the agent cannot see its own past decisions or the owner's coaching when deciding (Fable). Monet: `vector-db.ts` stores only SEC filings; the referenced `findRelevantExperiences`/`upsertExperiences` don't exist, so aggregate scorecards wash out the setup-specific structure the LLM reasons best over. **How:** add a second retrieval pass per run/candidate over doc types `['socratic-decision','coach-note','lesson-rollup']`, query built as a situation sketch (regime + thesis tag + evidence, not the generic filings query); on every closed lot embed a state vector (8 factor sub-scores + `entryMarketRegime` + macro snapshot + thesisTag + sector, optional Voyage-embedded rationale) with realized `{returnPct, holdingDays, riskExit, mae, mfe}` metadata into a dedicated namespace keyed by `proposalId`; k-NN retrieve 5–10 closest priors and inject as labeled "Closest historical analogs" + "Owner coaching" blocks into both Bull and Bear, top-analog similarity shown; write hook in `performance.recordFillFromProposal`, read hook in `proposeTrades`; new `src/lib/experience-memory.ts`; exclude same-run/future neighbors and stamp as-of. (builds on t19, t158, t159) **[high / M-L]**

**Build the outcome writer: matured outcomes finally land on decision cases** [Fable] — `SocraticDecisionCase.outcome` exists (`types.ts:982`) but no code path ever writes it; cases are upserted once at proposal time (`strategy.ts:835`) so step 5 of the loop is a permanent stub, and everything downstream (lessons, analogs, usefulness, harness) is blocked on it (four experts filed it). **How:** scheduled maturation job (piggyback the counterfactual cadence) joins placed decisions to `fill_events`/closed lots and blocked/skipped/rejected decisions to counterfactual forward returns from refPrice; writes `outcome` + `measuredAt`, emits a receipt per closed case, triggers re-index. (builds on t121, t61) **[high / M]**

**Multi-horizon (15m/1h/1d/1w), SPY-relative, vs-alternatives outcome schema** [Both] — Every learner is single-horizon: counterfactuals mature at one 5-day window (`counterfactual-learning.ts:16`, `DEFAULT_HORIZON_DAYS=5`), excursions are daily-bar only, outcome is one `returnPct` — so short-horizon thesis quality is unmeasurable and skipped-vs-taken comparisons are apples-to-oranges (both). Monet adds: IC at 5d optimizes weights for a horizon the strategy may not trade. **How:** replace the scalar with `outcomes[]: {horizon 15m|1h|1d|1w, returnPct, spyExcessPct, altReturnPct, maturedAt, priceBasis, resolution ok|unresolvable(reason)}` on decision cases AND skipped-counterfactual rows; forward-sample 15m/1h from live quotes at placement, 1d/1w from daily closes; compute multi-horizon IC (1/5/20/60 trading days) in `buildFactorObservations`/`computeFactorICs` and let the tuner target each thesis's median realized `holdingDays`; report the IC term structure; render the horizon ladder on Outcomes with skipped + taken on one grid. (builds on t121, t126, t88) **[high / L]**

**Close the per-model loop: per-model scoreboard + calibration + rotation/bandit** [Both] — `proposedByModel` is persisted but nothing aggregates realized win-rate/avg-return/IC/P&L by model; `getConfidenceCalibration` pools all closed lots regardless of proposing model (`performance.ts:915-929`) so one overconfident model corrupts the shared curve `calibrationSizing` multiplies into notional (`strategy.ts:1637-1640`); `manager-model-options.md` claims a per-model breakdown that does not exist in code. **How:** `getModelScorecard`/`getPerModelPerformance` in `performance.ts` (reuse `aggregateClosedLots` with key `lot.proposedByModel`, thread onto `ClosedLot`); reuse `pairedICDiffStats` for a paired candidate-vs-baseline t-stat between models over the same snapshot dates; group calibration by band×model with the per-band minTrades gate and pooled fallback; deterministic per-run assignment `hash(runId or userId+day)→bucket` over `strategistModelSet` for unbiased arms, upgrading to Thompson-sampling/epsilon-greedy contextual bandit (per-model shrunk win-rate conditioned on regime, explore floor); surface per-model reliability curves on Results, ranking the A/B on calibration not just P&L; owner override intact. (builds on t119) **[high / M]**

**Coaching becomes durable learning (ingestLearned + re-index; kill slice(-20))** [Fable] — Coach notes are bare strings capped at `slice(-20)` (`db-socratic.ts:263` — the 21st note silently deletes the oldest with no receipt), never pass through `ingestLearned`, never reach any prompt: exactly the "chat history" failure the vision rejects. **How:** on append, (a) re-index the memory doc; (b) run the note through `ingestLearned` with new origin `coach` — fact tier lands a durable `learned_context` row linked to the decision, risk/directive tier routes to the approval inbox; (c) replace `slice(-20)` with archival + receipt; (d) tag later retrievals "coached" with "promoted to durable lesson" provenance. (builds on t19, t122) **[high / M]**

**Decompose reflection into structured, regime/thesis-conditioned, retrievable lessons** [Both] — `generateReflectionSummary` writes ONE ≤130-word per-account blob injected wholesale into every Bull prompt regardless of regime (`post-mortem.ts`, `strategy.ts:2466`); `retrieveLearnedContext` accepts a `regime` arg that "is not yet used as a filter," so a high-VIX-panic lesson is fed verbatim in a calm trend (both). Lossy, drift-prone, cache-busting; the structured `writeThesisTrackRecordFacts` sink already exists and is better. **How:** decompose into discrete tagged lesson rows (regime, thesisTag, dominantFactor) stored in `learned_context` AND embedded as `doc_type="lesson"` carrying realized win-rate/MAE-MFE/capturePct; wire `retrieveLearnedContext` (`learned-context/store.ts`) to filter/boost by current run regime (`determineMarketRegime`) and candidate theses; gate emission on a min sample with regime-agnostic fallback for thin regimes; demote the free-text blob out of the system prompt (keep as fallback). (See A2/B21/C7.) **[high / M]**

(builds on t3, t60) **[high / S]**

**Real per-decision lessons at maturation — replace the template strings** [Fable] — `lessons` on every case are static templates written at creation ("Track realized outcome against the stated thesis…", `socratic-runtime.ts:375-379`). **How:** when the outcome job closes a case, run a small budget-gated post-mortem pass (belief + dissent + evidence vs realized multi-horizon outcome) → 1-3 concrete lessons with direction (repeat/avoid/adjust-sizing/adjust-timing) plus `{verdictOnBelief, whichDissentMattered, coachQuestion}`; write to `lessons[]`, re-index, route each through `ingestLearned` (origin `autonomous`). (builds on t121, t122) **[high / M]**

**Belief object at run level: persist the thesis-of-the-day and its revisions** [Fable] — Step 1 has no artifact: per-trade thesisTags exist but the run-level market belief lives only in run-summary prose, invisible to RAG and the owner. **How:** persist a per-run `MarketBelief {statement, regime, keyEvidence refs, confidence, contradicts (prior belief id)}` as a structured schema field; index into memory; belief timeline in the Live Thesis section; feed the 2-3 most recent beliefs into the next run as explicit prior context. **[high / L]**

### Medium impact

**Feed owner-approved risk-tier learned rows back into prompts** [Fable] — `applyApprovedPending` promotes approved risk rows, but `listLearnedContextForDecision` hard-filters `risk_tier='fact'` (`db-learning.ts`), so an owner-approved item never reaches any prompt — the approval inbox is a write-only ritual. **How:** return live risk rows in a labeled "OWNER-APPROVED GUIDANCE (advisory)" block with approval date; keep the never-feeds-deterministic-sizing invariant. (builds on t19) **[medium / S]**

**Stamp injected learned-context fact ids per run; make the fact store as-of reconstructable** [Fable] — Nothing records which fact rows entered a prompt (`strategy.ts:535-546`) and the store is a current-state view (supersede/expiry unreplayable). **How:** stamp fact ids + rendered text into the run-input bundle; add `listLearnedContextAsOf` replaying the supersede/expiry chain so the harness can toggle individual facts. (builds on t19) **[medium / S]**

**Embed coach notes and accepted framework text as their own retrievable vectors** [Fable] — A coaching theme spread across many notes ("consistently timid on high-conviction entries") has no retrievable representation. **How:** store each note as doc_type `coach-note` ({symbol, thesis_tag, regime, decision_id}) and accepted proposals as `framework-decision`; include both in decision-time retrieval so the agent re-reads its coach before similar decisions. **[medium / S]**

**Exit-side counterfactuals: post-exit regret tracking** [Fable] — The counterfactual pipeline covers only openings (`strategy.ts:1006-1008`); once a lot closes the symbol is never looked at again, so "sold too early" has zero data. **How:** on every sell/cover fill insert an exit-counterfactual row into the same maturation pipeline; compute held-alternative vs realized, benchmark-relative and sign-adjusted; aggregate an exit-quality scorecard per thesis and exit type. (builds on t121) **[medium / M]**

**Executed-trade alternatives: 'waited' and size-ladder counterfactuals** [Fable] — Executed fills store one realized path; no "if we had waited a day" entry delta or "at 2×/0.5× size" P&L exists, so "thesis right but sizing timid" has no quantitative anchor. **How:** store next-day/next-run entry-price delta and lot P&L rescaled to the pre-cap `advisedNotional` (`strategy.ts:1700`); render "sizing caps cost/saved $X" per cap reason. (builds on t121) **[medium / M]**

**Hierarchical partial pooling across the owner's accounts (kill the fixed neutral prior)** [Monet] — Every scorecard shrinks toward a fixed 50%/0% prior and each account must independently reach ≥20 closed lots before weights move, so a new/thin account borrows no strength. **How:** empirical-Bayes / James-Stein / Beta-Binomial in `aggregateClosedLots` (`resolveShrinkPrior` is the seam) estimating the population mean per thesis×regime across the owner's accounts (or the opt-in shared tier) and shrinking each account toward that data-driven prior; aggregate only within one owner's accounts, never leaking another user's outcomes. **[medium / L]**

**Drift / change-point detection + time-decay weighting** [Monet] — Scorecards aggregate the last 500 fill events with no recency weighting (an 18-month-old lot counts as much as last week's) and no CUSUM/Page-Hinkley monitor on realized IC/win-rate. **How:** exponential time-decay (half-life ~60–90 trading days) in scorecard aggregation + a Page-Hinkley/CUSUM detector on the per-date OOS IC series in `backtest.ts`; on a downward change-point, widen exploration, discount pre-break history, notify. Couple with the hierarchical prior. (Converges with E13.) **[medium / M]**

**Exploration policy + inverse-propensity correction (de-bias the whole eval stack)** [Monet] — Positive outcomes come only from names the strategy chose with the weights being tuned (a closed loop); skipped counterfactuals cover only top-25-by-score, so deep-underdog names are never sampled and factor ICs are estimated on a truncated endogenous slice — every downstream statistic (IC, per-model scoreboard, calibration) inherits the bias. **How:** small owner-overridable exploration budget (epsilon or Thompson sampling on factor-weight posteriors → floor position in a lower-ranked candidate) + IPS/doubly-robust weighting when computing factor ICs; the counterfactual materializer is the natural home for propensity bookkeeping. (Converges with CC6.) **[medium / L]**

**Missed-opportunity nudge is one-sided (up-only) and bypasses the OOS gate** [Monet] — `applyMissedOpportunityNudge` only ADDS weight to a factor recurring among missed winners, never down-weights a factor dominating skipped names that fell, and it is this-run-only, biasing weights monotonically upward. **How:** make the nudge symmetric (down-weight a factor recurring among skipped losers using the existing winner/loser hit-rate machinery) and route the persistent version through `applyAutonomousWeightTuning` so it only sticks if it survives walk-forward. **[medium / S]**

**OPRO-style prompt self-optimization; prune AI-LEARNED directive blocks** [Monet] — §3.D.3 calls for OPRO auto-pruning ("still TODO"); `mergeStrategyDirectiveBlock` only appends, so the strategy prompt grows monotonically and carries stale rules from prior regimes, and the offline eval isn't used to optimize the prompt. **How:** offline prompt-optimization loop (OPRO/APE/DSPy-style) — generate candidate directive edits, score on the deterministic offline eval + a held-out `signal_snapshot` slice, keep only improving edits; tag each AI-LEARNED block with its regime and prune directives not validated recently; version every change through `learning_mutations`; human-approved apply. **[medium / L]**

**Route reflection through framework-proposal governance instead of silently rewriting the Bull prompt** [Fable] — The ≤130-word reflection is overwrite-only and injected verbatim into the Bull system prompt every run (`strategy.ts:2466`) with no owner review, versioning, or overfitting guard. **How:** reflection call emits structured lesson candidates `{lesson, evidence, affectedTheses, confidence}` (forced tool); file each as a framework proposal; accepted lessons become numbered, dated doctrine lines with provenance; rejections are receipts — one pipeline with coaching-becomes-doctrine. (builds on t122) **[medium / M]**

**Promote signal_snapshot to a first-class indexed table** [Monet] — `getFactorScorecard`/`getSignalEfficacy` resolve entry factors by scanning `listAudit(500)`; once a run ages past 500 rows attribution falls back to the persisted `dominantFactor` only and full `factorBreakdown`/bulletin context is lost — exactly for the long-horizon trades most valuable to learn from. **How:** `signal_snapshot` table (`run_id, symbol, factor_breakdown JSON, regime, bulletins, chosen`) with retention independent of the audit ring, queried directly; `db.ts migrate()` adds it; dual-read during transition. **[medium / M]**

**Overlap-aware IC standard errors (the auto-apply gate's paired-t is overstated)** [Monet] — `backtest.ts` computes per-date ICs against a 5-day forward return but `pairedICDiffStats` derives `seDiff = std/sqrt(n)` assuming i.i.d. per-date diffs, while 5-day-overlap windows are heavily autocorrelated (effective n ≈ n/5), so the t-stat feeding `minOosPairedTStat` is inflated — exactly how overfit weights get auto-applied. **How:** replace the naive SE with Newey-West/HAC (lag = `horizonDays−1`) on the per-date IC-difference series, or a stationary/block bootstrap (block ≈ horizon), or de-overlap by subsampling every horizon-th date; apply the same to `oosICIR`; document that the stricter SE is the safe direction. **[high / M]**

**Receipts are the control plane but the audit log is not tamper-evident** [Fable] — `audit()` is a plain INSERT (`db.ts:457-460`): no hash chaining, no sequence integrity, and the app ships a delete path over the table, so anything with a DB handle can rewrite the very receipts the philosophy depends on; Litestream gives off-box copies but cannot prove rows weren't modified pre-replication. **How:** a per-row `prev_hash` chain computed inside `audit()`; periodic anchor of the chain head to an external sink the DB writer can't rewrite (Sentry event, object-locked R2, or the usage-monitor ingest); a verify-chain admin endpoint; GDPR deletion leaves a signed tombstone so truncation is distinguishable from tampering.

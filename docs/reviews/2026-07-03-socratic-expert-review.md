# Socratic Trade — Expert Panel Review (Definitive Synthesis)

**Date:** 2026-07-03
**Input:** 267 improvements from 8 domain experts (ml-learning, rag-embeddings, llm-prompting-finance, markets-trading, decision-wisdom, ui-ux, data-engineering, memory-architecture) plus 3 gap-filler passes (adversarial security, operational resilience, backtest/doctrine validation). After merging true duplicates: **209 distinct items**. Backlog cross-references ("builds on tNN") point at `inventory-compact.tsv`.

## Executive summary

The panel's unanimous conclusion: the Socratic refocus is the right product, and almost none of its seven-step loop actually runs yet — the codebase has the *schemas* for a trading mind (decision cases, memory indexing, coach notes, framework proposals, outcome fields, invalidation text) but nearly every loop is open at one end. Concretely: decision memories are written but never retrieved (strategy.ts:513 filters memory out of every retrieval); `outcome` has no writer anywhere, so every case and every embedded memory says "pending" forever; coach notes die in a silently-truncating `slice(-20)` array and never reach a prompt; framework acceptance is a status flip that changes nothing; dissent is a `{rejected, reason}` boolean; and one outright bug (the Bear schema strips `confidenceScore`, killing the approval-time debate trigger and neutering conviction sizing) shows the money path is under-tested. Four experts independently filed the same five closures — write outcomes (multi-horizon, SPY-relative), read memory back at decision time, re-index on every lifecycle change, make coaching durable, make framework acceptance actuate a diff — which makes them the unambiguous critical path. Around that core, the gap-fillers add the consequence of the owner's "everything advisory, receipts are the control plane" philosophy: if receipts are the only control, then receipt honesty (injection flags, trust tiers, provenance, tamper-evidence, statistical honesty with n/CI, crash/reconciliation receipts) is security- and correctness-critical work, not polish. This is the "built-but-unwired rigor" meta-theme of the 2026-06-30 audit, now applied to the product's soul.

## Top 15 highest-leverage improvements

1. **Build the outcome writer: matured outcomes finally land on decision cases** [memory-learning, high/M] — step 5 of the loop does not exist; four experts filed it independently; everything downstream (lessons, analogs, usefulness, harness) is blocked on it.
2. **Retrieve episodic decision memory (closest historical analogs) at decision time** [memory-learning, high/M] — memory is write-only; the "trading mind with memory" cannot remember; four experts filed it.
3. **Multi-horizon (15m/1h/1d/1w), SPY-relative, vs-alternatives outcome schema** [memory-learning, high/L] — the vision's stated outcome model; also the truth column for every future validation.
4. **Coaching becomes durable learning (ingestLearned + re-index; kill slice(-20))** [memory-learning, high/M] — the core product promise is currently false; the 21st note deletes the 1st with no receipt.
5. **Fix the Bear schema silently stripping confidenceScore** [llm-prompting, high/S] — a live money-path bug: the approval-time Red Team never triggers and sizing falls back to neutral 50 for every Bear-surviving proposal.
6. **Re-index decision memory on every lifecycle update** [memory-learning, high/S] — cheap; without it, items 1–4 produce memories frozen at "pending".
7. **Belief / iMayBeWrongIf / reversalTriggers / evidenceRefs as first-class proposal schema fields** [llm-prompting, high/M] — steps 1 and 4 currently have no home in the model's output; the UI cannot render what the model was never asked for.
8. **Reversal triggers on every opening + an invalidation watcher** [memory-learning, high/L] — stated dissent is dead text today; monitoring it is what makes dissent an object rather than prose.
9. **Non-actions become first-class case files (passedOn + run-level 'waited' cases)** [memory-learning, high/M] — six experts converged on it; restraint is currently invisible to memory, coaching, and the harness.
10. **Decision-trace inspector at /console/decisions/[id]** [ui-ux, high/L] — the product's core object cannot be opened; coach/memory/outcome surfaces all anchor here.
11. **Framework-proposal actuation: 'accepted' produces a reviewable, applied diff** [decision-wisdom, high/L] — step 7 currently dead-ends at a database enum; three experts filed it.
12. **Doctrine version ledger stamped onto every decision** [memory-learning, high/M] — without it no decision can ever be replayed against the philosophy that produced it.
13. **Replace the string-matching override classifier with structured reason codes** [decision-wisdom, high/M] — the load-bearing wall of "nothing is hard except the account" is substring matching on prose that any rewording silently flips.
14. **Fence untrusted text in money-path prompts + injection-attempt receipts** [llm-prompting, high/M] — with all guardrails advisory, a poisoned headline can chain Bull→Bear→override to 100%-NAV execution; detection-as-receipt is the philosophy-compatible control.
15. **Per-run decision-input bundle (frozen prompt inputs) + shipped-default flip of socraticOverrideMode to 'propose'** [decision-wisdom, high/M] — replayability substrate for the doctrine harness and manager A/B, plus the one default the security pass says is a config accident waiting for its first poisoned headline.

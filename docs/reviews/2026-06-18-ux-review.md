# UX & site structure — review (2026-06-18)

Source: the `platform-deep-review` multi-agent workflow (UX track: 7 dimensions, 34 findings
confirmed before the run hit the session limit). The adversarial-verify + synthesis stages were
cut off by the limit, so this report was reconstructed from the reviewers' findings; treat
severities as reviewer-assigned and confirm before acting. Findings are grounded in
`app/dashboard-client.tsx`, `app/ui/*`, and `app/page.tsx`.

## Executive summary
The cockpit is dense and powerful but assumes an expert who already understands the paper/live
model. The biggest gaps are **(1) safety legibility** (paper vs live, and what "autonomy"/"Run"
actually do are easy to misread for an app that can place real trades), **(2) onboarding** (no
first-run path to connect an account or learn the model; most empty states dead-end), and
**(3) accessibility** (no mobile viewport, tabs/overlays lack ARIA + focus management, several
inputs unlabeled, low contrast). These are the areas where mainstream platforms (Robinhood,
Composer, Wealthfront) feel far more trustworthy and approachable.

## Top priorities
1. **Paper vs Live is not legible enough** — mode is easy to miss; an app that can place real
   orders should make live state unmistakable (persistent banner/color, confirm on entering
   live). *(trust-safety)*
2. **"Run" / approve place trades without a confirm step in places** — approving a proposal and
   the Run button can fire irreversible actions with inconsistent confirmation patterns; add a
   uniform confirm for any state-changing/trading action (kill switch already confirms — match it).
3. **No first-run / onboarding path** — a new user lands with no guided "connect an account →
   pick paper → run once" flow. Add a first-run checklist/empty-state CTA that opens the new
   Accounts modal. *(onboarding)*
4. **Most empty states are dead ends** — they describe emptiness but don't link to the next
   action (run scan, connect account, open settings). Make every empty state actionable.
5. **No risk/loss disclosure** — there is no "estimates, not advice / trading involves risk"
   surface; expected for a trading app and for trust.

## Accessibility (group — high collective impact)
- **No viewport meta tag** → not responsive on mobile; layout breaks below lg/xl breakpoints.
- **Tabs not associated with panels** (no `role=tablist/tab/tabpanel` + `aria-controls`).
- **Command palette lacks dialog semantics**; active tab/overlays are not focus-managed
  (no focus trap / return focus on close).
- **Sortable scan headers and clickable rows aren't keyboard-accessible** (div/onClick, no
  `button`/`tabindex`/Enter handling).
- **Range sliders and several inputs are unlabeled**; **low-contrast faint text** fails WCAG AA.
- **No live region** announces async updates (scan refresh, run results) to screen readers.
- **"Strategy Flow" is labeled ambiguously** / not described for AT.

## Information architecture & interaction
- **Account switcher overloads a `<select>`** with a "Manage Accounts…" action (now split into a
  dedicated Accounts modal this session — keep going: the switcher could become a proper menu).
- **Header command bar is cramped**; consider grouping run/kill/settings and surfacing mode there.
- **Symbol drilldown "AI Conviction" framing** may overstate; label it as heuristic.
- **Daily-risk severity coloring** is inconsistent across the UI.

## Competitor-informed enhancements
- Robinhood/Wealthfront: a calm, progressive-disclosure first screen; one obvious primary action.
- Composer.trade: explicit "this is a backtest/paper vs live" framing and a strategy-state header.
- TradingView: keyboard-first tables, persistent symbol search, dense-but-legible theming.
- Bloomberg/OpenBB: a status/command line; we have ⌘K — make it discoverable and a11y-correct.

## Quick wins (high value / low effort)
- Add the viewport meta tag.
- Label inputs/sliders; bump faint-text contrast.
- Make every empty state link to its next action.
- Wire ARIA roles on the tab bar (ids already exist).
- Uniform confirm on Run / approve (reuse the kill-switch ConfirmModal).
- Persistent Live-mode banner/badge.

## Larger initiatives
- First-run onboarding flow + guided account connection.
- Full keyboard/AT pass on tables, palette, and overlays (focus trap, live regions).
- Responsive layout for tablet/mobile.

## Done this session
- Account management split into a dedicated **Accounts** modal (separate from Settings), opened
  from the switcher and ⌘K ("Manage accounts").
- Market Scan tickers now render via the shared `SymbolButton` (underline ticker style used
  app-wide), so they match tickers elsewhere, are keyboard-accessible, and open the company
  drilldown drawer on click (partially addresses the "clickable rows not keyboard accessible"
  a11y finding for the symbol column).

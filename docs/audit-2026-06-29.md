## Top 5 highest-ROI fixes

1. **Move secrets out of `.env.local`** → Infisical is already integrated (`npm run dev:secrets`). Move all 17 secrets there. Eliminates the single biggest security risk.

2. **Add a persistent cache layer** → Even a simple SQLite-based cache table with TTL would survive restarts. Eliminates cold-start penalty on every deploy/restart.

3. **Add request coalescing** → A Promise-based `Map<string, Promise<T>>` pending-requests pattern in `history.ts` and `data-providers.ts`. ~20 lines of code. Eliminates duplicate provider cascades on multi-widget dashboards.

4. **Add HTTP cache headers** → `Cache-Control: public, max-age=30` on scan data, `max-age=86400` on historical OHLC. Eliminates redundant server hits from the same client.

5. **Write strategy loop tests** → Even a single integration test that mocks the LLM and broker and verifies the proposal→evaluate→insert pipeline works. Catches regressions in the money path before they reach production.

## Dimension summaries

### Architecture

The project follows Next.js 16 App Router conventions well — thin API routes calling `src/lib/` functions. The database barrel-file split (`db.ts` → `db-*.ts`) is a good pattern. The main structural problems are:

- **3 files over 2,700 lines** (`dashboard-client.tsx` 6,416, `data-providers.ts` 2,870, `strategy.ts` 2,777)
- **`src/lib/` is a monolith** — 60 flat files, only a few domain subdirectories
- **12 stale `* 2.ts` duplicates** from merge conflicts
- **`types.ts` is a 1,296-line kitchen sink** — types should be co-located

### Security

**One critical:** 17+ plaintext secrets on disk in `.env.local` including the encryption master key and Alpaca broker credentials.

The previously-critical IDOR vulnerability (client-supplied `userId`) is **fixed** — `resolveRequestUserId()` now explicitly ignores the body parameter. The auth middleware is well-designed with three-tier identity resolution.

Gaps: timing-safe token comparison missing, no rate limiting on expensive endpoints (chat, scan, keys), Robinhood OAuth tokens stored unencrypted, Auth.js is beta.

### Performance

**The central theme: no caching.** All caches are in-memory Maps, wiped on restart. No HTTP cache headers. No request coalescing. No embedding cache.

The provider cascade architecture is well-designed for resilience but expensive — sequential provider fallback in history means 30s+ worst-case, and the enrichment cascade fires 3-5 API calls per symbol.

Quick wins: request coalescing (~20 lines), HTTP cache headers (~10 lines per route), and an LRU embedding cache would yield dramatic improvements with minimal code.

### Testing & Reliability

**The gap is concentrated:** zero tests for the core modules that handle real money — `strategy.ts`, broker gateways, and the entire DB layer. Tests that exist are well-written (40+ cases in `policy.test.ts`, real HTML fixtures in `web-sources.test.ts`) but the most critical code paths are untested.

Error handling is generally strong — isolated per-proposal errors, cascading provider fallbacks, audit events for every significant action. Gaps: strategy outer catch is too coarse, fire-and-forget promises have no monitoring, no circuit breakers for external APIs.

### Features & UX

The dashboard is feature-rich but buried in a single 6,416-line component. The **biggest UX gap is onboarding** — new users get a dashboard with red readiness indicators and zero guidance. Accessibility is inconsistent (no skip-to-content, color-only P&L indicators, no heading hierarchy). The trade workflow (proposal → review → approve → execute → monitor) is complete and well-designed.

New uncommitted features (RAG coverage admin, confirmation modal, RAG metering, market calendar) are incrementally improving observability and safety.

### RAG & AI Pipeline

The pipeline architecture is sophisticated: Bull Agent + deterministic pre-filter + Bear Agent + optional cross-provider Red Team debate. The learning loop (counterfactual tracking, thesis/regime scorecards, Bayesian shrinkage, post-mortem reflection) is well-designed.

**Cost is the main concern:** up to 4 LLM calls per cycle with no embedding cache, no streaming on chat, and fixed 5x over-fetch for reranking. Embedding caching alone would cut Voyage costs 50–80%.

**Quality improvements:** sentence-aware chunking (current word-level window splits mid-phrase), multi-query retrieval strategies, and a feedback loop measuring whether RAG context actually changes LLM behavior.

## What

Ports the App Store Connect credential hardening (AFC-459, revision 2) into Socratic-Trade.  The private key is a secret, and the approved sources are the process environment, a captured `fleet-secrets get` and bootstrap-only Keychain credentials.  A path on disk is not one of them, so the node client never reads a key file:  the shell layer that already owns the credential resolves it and hands the key over in `ASC_KEY_P8`, so the key is never an argument, never on stdout and never in a log line.

This is the revision-2 shape the CodeCaps reviewer approved, as landed in [CodeCaps PR #271](https://github.com/Simple-With-Us/CodeCaps/pull/271):  revision 1 hardened a file reader, and a hardened reader is still a file read, so revision 2 removes the file read entirely.

## Changes

- `scripts/ios-fleet/asc-key.mjs` (new) — the key module.  It is the approved CodeCaps reference with one change:  `normalizePrivateKey` turns literal backslash-n separators into newlines, so the shell layer, the module and the client agree on what a key is.  It validates a PEM, writes the mode-600 materialization that `altool` and Xcode read, and builds an allowlisted child environment.  It never reads a file:  there is no `readPrivateKeyFile`, no `execWithKey`, no `O_NOFOLLOW` read and no `read` or `exec` subcommand.
- `scripts/ios-fleet/asc-api.mjs` — `resolveAscCredentials()` now takes the first source that is present:  the `APPLE_API_*` trio, then `ASC_KEY_ID` / `ASC_ISSUER_ID` / `ASC_KEY_P8`, then Fleet-OPS prod `/asc` through `fleet-secrets`.  The `ASC_KEY_PATH` branch and the `privateKeyPem = keyPem || readFileSync(keyPath, "utf8")` fallback are gone, the PEM is validated with `normalizePrivateKey`, and the refusal names the three sources and says that a path in `ASC_KEY_PATH` is not a credential source.  An issuer named in the environment belongs to the key named with it, so it is trusted only when the environment named the key id too.  A refused value carries a masked preview of the PEM body, the first eight and the last four characters.
- `scripts/ios-fleet/ship-testflight.sh` — `load_secrets` resolves an ambient `ASC_KEY_P8` first, falls back to Infisical `/asc` (or `/authkey-<id>-p8` for a key id that is not the `/asc` one), writes the mode-600 staging file for `altool` and Xcode, and exports the key to the client in the environment.  A named `ASC_KEY_PATH` is ignored, and the run says so in a log line.  A missing credential is fatal where it is required, before the upload, and names what is missing;  a refused `ASC_KEY_P8` is fatal with a masked preview instead of a silent fallback to a different key.
- `scripts/ios-fleet/test-asc-key.test.mjs` (new) — the module tests, plus the client driven against a loopback server.  The request is verified against the environment key and against the key in the named file, so "the environment wins over a named file" is proven rather than asserted.
- `scripts/ios-fleet/test-asc-credentials.sh` (new) — the credential-precedence test.  Every comparison answers through the exit code of a node helper, so a credential is never expanded into the shell, and a scanner proves the ship script never captures the key material into a variable.
- `scripts/ios-fleet/asc-api.credentials.test.mjs` — updated for the new source order instead of the removed file branch, and it pins that an environment issuer is never paired with the `/asc` key.
- `scripts/ios-asc-key-env.sh` (new) — the hosted-job credential handoff:  it fetches the key from Infisical prod and execs the child with `ASC_KEY_P8` in its environment, so the key never crosses a step boundary and the environment file never holds it.
- `scripts/test-ios-asc-key-env.sh` (new) — the offline test for that handoff, with a fake Infisical CLI.
- `.github/workflows/ios-ship.yml` — the ship step fetches the key through that helper, so the client has a credential in the hosted job.  The mode-600 staged file stays the materialization for the Apple tools that need a key on disk.
- `scripts/ios-fleet.sha256` and `scripts/ios-fleet-pin.sh` — the new module joins the pinned runtime set, and the pin is refreshed in this change.
- `scripts/ios-fleet/check-drift.sh` and `scripts/ios-fleet/README.md` — the new file joins the runtime install set, and the documented credential order matches the code.
- `.github/workflows/ci.yml` — the two new offline suites run in the iOS ship-gate job, so they are real gates.
- `.gitleaksignore` — the fingerprint for the two intermediate commits that carried the fake PEM fixture, which is the repository's own mechanism for a fixture like this.
- `STATUS.md`, `PLAN.md` and `docs/rollouts/2026-10-21-afc459-asc-credential-hardening.md` — the handoff notes the repo's own pre-commit protocol asks for.

## Repo-specific notes

- This repo's client is shape B (`resolveAscCredentials()`), so the credential block was rewritten in place rather than replaced.
- The shell layer names its Infisical helper `fleet_secret_get` and its cleanup `asc_cleanup`, so the ported credential test drives those names instead of the reference's `fs_get` and `cleanup_asc_tmp`.
- The reference `test-asc-key.test.mjs` still covered revision 1 (it imported `readPrivateKeyFile` and drove the `read` and `exec` subcommands), so the suite here was written for revision 2:  it asserts the module's four exports, asserts that the module text contains no file read and no `read`/`exec` subcommand, and drives the real client.
- The client had no `APPLE_API_*` support, so the first tier was added with the reference's semantics.
- `readFileSync` and `existsSync` had no other use in the client, so the import is gone.
- This repository's workflow keeps key material out of the environment file, and `scripts/test-ios-stage-asc-key.sh` enforces it.  That is why the hosted step fetches the key itself instead of publishing it between steps.

## Review

Every finding in review was fixed in code, and the threads are answered:

- The hosted job had no credential, because the workflow published only `ASC_KEY_PATH`.  Reading the path back would be the defect this change removes, so the ship step fetches the key itself, through `scripts/ios-asc-key-env.sh`, and hands it over in that step's own environment.
- A PEM stored with literal backslash-n separators was refused.  `normalizePrivateKey` now undoes the separators, in the one place the shell layer, the module and the client all use.
- An environment issuer was paired with the `/asc` key.  An issuer belongs to the key named with it, so it is trusted only when the environment named the key id too.
- A missing credential returned success.  It is fatal where it is required, before the upload, and names what is missing.  The early call keeps reporting it, because the build phase may never reach App Store Connect, which the repository's own ship-sequence suite asserts.
- A refused key was discarded and replaced by a fallback.  It is fatal now, with a masked preview of the PEM body, so the value that failed can be identified without the key material being printed.
